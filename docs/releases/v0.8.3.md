# GoodMemory 0.8.3

Explicit English project decisions now become durable facts through ordinary,
unannotated `remember` calls. The reported sentence beginning `Project decision:
When SQLite reports SQLITE_BUSY_SNAPSHOT, ...` was retained only as source text
in 0.8.2 because the rules did not recognize the declaration and treated a
leading `When` as an unresolved question.

The English language pack now recognizes project/repository/repo decision
declarations and distinguishes conditional operational rules from questions.
The full rule, including its rollback and fresh-read steps, remains in the
fact and its source evidence. Existing assistant-role, attribution, and policy
restrictions still apply. The English analyzer version is updated so derived
projections observe the new language-pack identity.

This release also includes the changes already on main after 0.8.2: apply
feedback eligibility before recall capacity limits, and allow SQLite storage
initialization to recover after a transient failure.

Upgrade with `npm install goodmemory@0.8.3` (or the corresponding global install
for CLI use). Re-send a previously source-only decision after upgrading;
upgrading does not automatically re-extract old transcripts.

Regression coverage includes the exact reported wording, unrelated operational
decisions, conditional policies, question/placeholder/report exclusions,
SQLite persistence and recall through a fresh facade, evidence provenance,
workspace isolation, assistant/system sources, and policy denial. DSH's
separate-process integration verifies the actual managed HTTP/Bun path in
the dsh-goodmemory repository. These scripted checks make no answer-quality,
coding-benefit, or Windows-runtime claim.

The release manifest and evidence archive are the authority for the complete
release-gate results and exact package identity.
