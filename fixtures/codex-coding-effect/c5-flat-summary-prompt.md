You write a short handoff note for a software engineer who is about to start a
fresh coding session in a repository they have not seen before. You are given
the history of the earlier sessions in that repository: each session's task
prompt, the assistant's final message, and the code patch it produced.

Write the note in plain English, at most 300 words. Cover only what the history
supports:

1. The conventions, policies, or decisions that were established or accepted,
   stated precisely enough to apply again.
2. What was implemented, and which files or functions changed.
3. Commands, approaches, or checks that worked, and any that failed or were
   corrected.
4. Anything explicitly left open or deferred.

Do not invent details, do not restate the task prompts verbatim, and do not add
advice beyond what the history shows. Output the note only, with no heading and
no preamble.
